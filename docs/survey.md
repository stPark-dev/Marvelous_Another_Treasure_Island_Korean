## 2. 확정 사실 (텍스트 경로)

- **스크립트**: ROM 0x21B400–0x23BF9D(E1:B400~), 비압축 단일 블록, FF로 끝남. 메시지 3,076개(빈 메시지 38), 134,045 B. 뒤 여유 FF 2,146 B.
- **포인터**: ROM에 없음. 부팅 때 SA-1 루틴 00:FC7B가 스크립트를 처음부터 스캔해 FA/FB 다음 위치를 BW-RAM 40:DBE0에 3바이트씩 기록(길이표 00:FB5E, FE 인자 길이표 00:FBFB). 스크립트 기준 주소를 참조하는 곳은 빌더의 즉치값 두 곳(파일 0x7C83, 0x7C8C)뿐.
  - 메시지 길이를 바꿔도 포인터 테이블 수정 불필요. 단 메시지 수는 BW-RAM 끝(0xFFFF)까지 약 3,082개가 상한이며, 현재 3,077개.
  - 빌더 길이표는 F4를 1바이트, F5를 2바이트로 셈(디코더와 다름). 인자 바이트가 FA/FB/FE/FF이면 경계가 어긋나므로 빌드에서 빌더 시뮬레이션으로 경계를 검증해야 함. 원본은 3,076개 전부 일치(`tools/mvscript.py`).
- **디코더**: S-CPU 9F:BA3A가 메시지를 렌더러 코드로 펼쳐 40:A400에 기록(빅엔디언 16비트 코드 + 1바이트 제어).
  - `00–F1`: 가나 페이지 1바이트 → 코드 2b, 2b+1. `F0`=전각 공백.
  - `FD xx`/`FC xx`/`F4 xx`: 한자 페이지 0/1/2 → 코드 0x200/0x400/0x600 + 2xx.
  - `F2 F3 F6 F7 F8 F9`: 1바이트 제어(F8 줄바꿈, F9 페이지 넘김, F6 선택지 내 줄바꿈 등). `F5 a b`: 삽입. `FA`/`FB`: 메시지 끝.
  - `FE 66 a b`(4), `FE 6D a`(3, 버튼 아이콘·숫자), `FE 7C …`(대형 폰트, FA/FB까지), 나머지 `FE xx`(2).
- **렌더러**: 9F:BCB1(대화), 98:9FD0(메뉴, 같은 40:A400 사용). 코드 하나 = 8×16 2bpp(32 B). 글자 하나 = 코드 2개 = 16×16. 코드 < 0x200 → ROM 0x2AC000(가나·영숫자), 0x200–0x7FF → ROM 0x270000(한자). 11비트 마스크.
- **대화 캔버스**: BW-RAM 40:9000, 368×48(16px 셀 23칸 × 3줄), 매 프레임 VRAM으로 DMA. Mode 5 고해상도.
- **폰트 용량**: 가나 페이지 241 + 한자 3페이지 768 슬롯 = 1,009글자. 원본 한자 사용 614자(페이지 2는 0x66 이후 다른 데이터).

## 6. 추가 조사 (2026-10-06, 같은 날 후속)

### 6.1 반각 띄어쓰기·한자 폰트 이전 (구현·런타임 검증)
- `F3`(원문 미사용, 렌더 제어 0x64는 진행 없는 RTS라 쓰이면 정지)를 디코더 표 9F:BA0E에서 0x65로 바꾸고, 렌더 표 9F:BC6B의 0x65 핸들러를 9F:FF9C(8px 전진)로 교체.
- 글자 렌더러는 반쪽 사이에서 9C 행 경계 보정을 하지 않음 → 0x?F에서 시작하는 글자가 깨짐. 공통 블릿 9F:BF97 진입부에 X 보정 헬퍼(9F:FFB2) 추가. 모든 BF97 호출부(17곳)가 X=9C×16임을 확인.
- 한자 경로 뱅크 즉치값 5곳(00:F32F, 98:A00F, 9F:BD91, 9F:D7C4, 9F:DFCD) E7→F4. 대형 폰트 경로(9F:BE5A, 9F:E0D1)는 E7 유지.
- 런타임: 메시지 1571 두 페이지(일반·[FE69] 스크롤 모드) 정상 표시.

### 6.2 대화창 폭
- 캔버스 한 행 = 16px 칸 22개(타일 0x500–0x54A). 넘치면 다음 행으로 선형 연결. 원문은 22칸 초과 줄 33개(공백으로 일부러 줄을 넘기거나 [F2] 이벤트 문구).
- 채택 범위: 한국어 한 줄 ≤22칸. 삽입 폭: 기본 `[FE6Dxx]` 아이콘 1칸, `[FE6D1A]` 팀 이름 5칸, `[FE6D34]/[FE6D56]` 리더 이름 4칸(9F:C8D7 표), 그 외 특수 삽입·숫자 3칸(보수적 추정).

### 6.3 이름(팀 이름)
- 저장: SA-1 I-RAM $310E–$3117, 글리프 번호 워드 5개, 빈칸 0x00F0. 입력 중에도 즉시 갱신.
- 표시: `[FE6D1A]` → 9F:C74A. 값 <0x200은 가나 폰트(9F:BDF2), ≥0x200은 대형 폰트와 같은 E7 경로(9F:BE49). 끝 공백은 9C를 되돌려 잘라냄.
- 리더 이름 `[FE6D34]`: 9F:C8D7 표(디온/맥스/잭 각 4글리프, 1바이트 글리프 번호).
- 미조사: 문자판(메시지 2973–2975) 셀 → 저장값 변환, 파일 선택 화면 등 다른 표시 소비자, SRAM 저장 형식.

### 6.4 그래픽 텍스트 (발견분)
- 게임 화면 오른쪽 명령 패널: 「?!」「チームワーク」「アイテム」「EXIT」 타일 그래픽.
- 하단 상태줄 「マーヴェラス」 로고, 장 시작 「－第1章－」, 타이틀 로고.

### 6.5 압축 자원, 타이틀, 인트로 (2026-10-06)
- 압축: SA-1 00:B904, LZ2 계열(명령 3비트+길이 5비트 / 0xE0 확장 10비트 / 0xC0 16비트 길이, 0xFF 종료, 복사 오프셋 빅엔디언 절대값). 포인터 표 249개: 하위 00:93D5, 상위 00:92DC, 뱅크 00:91E3. 코덱 `tools/lz2.py`.
- 타이틀: BG2 4bpp, 로고 타일 = 자원 53(VRAM 0x8000, 타일 512–767), 로고 맵 = 자원 56(BG2 맵 0–15행), 팔레트 7 색 1–14 = ROM 0x125B7C. 부제 「～もうひとつの宝島～」·TM = OBJ 자원 219(OBJ 타일 192~). 한글 로고(D11) = title_ko.png 상단(「마벨러스」)을 232px로 축소·14색 양자화·타일 병합(255개 이내), 부제는 Galmuri11-Bold 그라데이션으로 스프라이트 8칸에 그림. 런타임 확인.
- 인트로 이야기: BG3 2bpp 16×16 글리프 시트(자원 57–59, 192칸) + 32×64 맵(자원 60). 스크립트와 무관한 그림 텍스트. `data/intro_ko.json`의 줄을 원래 행·좌우 절반에 가운데 정렬. 런타임 확인.
- 장 시작 화면 「－第N章－」+제목: 메시지 2976을 글리프 풀로 위치 조합 → 위치 보존 번역으로 해결(런타임 확인).
- 대형 외침 그림(`FE 7C`): EC:E000(파일 0x2CE000)의 32×16 조각, 메시지 2947(「こらー！」+「いいかげんにしろ！」), 2949–2954(「ウッキ～」). 미처리.

### 6.6 다른 렌더러와 반각 공백 (2026-10-06, 런타임 회귀에서 발견)
- 렌더 제어 디스패치 표가 둘: 9F:BC65(대화), 9F:DEB6(캡션·초상화 창 등, 블릿 9F:E02E). 둘 다 0x65를 반각 공백 핸들러로, 블릿 진입부에 홀수 칸 보정. 미패치 상태에서는 반각 공백(F3)에서 진행이 멈춤(텐트 장면 메시지 2938에서 재현·수정 확인).
- 아이콘·숫자·이름 삽입(`[FE6Dxx]`, `[FE6B]`, `[FE6C]`)은 짝수 칸을 가정 → 인코더가 줄 안 홀수 위치면 반각 공백을 하나 더 넣어 정렬(`koenc.layout`). 수정 전후 초상화 창 메시지 32로 확인.
- 메뉴 렌더러(뱅크 98)는 0x62–0x7F 제어 처리 경로가 확인되지 않아, 아이템명(정책 item)은 공백을 전각으로 바꿔 인코딩.

### 6.7 조사 장면 그림(포스터·게시판·석판) (2026-10-06)

- 텐트 포스터 같은 "조사 화면"은 장면 번호 `$358C`(I-RAM)로 BG1 맵과 타일을 고른다. 표 두 개(파일 0x2F921F, 0x2F929B; 뱅크 9F는 EXB=2라 파일 0x2F8000부터):
  - `9F:921F[x]`: 맵 에셋 = 72 + (v >> 1), 절반 = v & 1 (에셋의 0x1000바이트 단위, BG1 64x32 맵 VRAM 0x5800).
  - `9F:929B[x]`: 타일 에셋 = 81 + (v >> 2), (v & 3) × 0x800바이트부터 4KB(128타일)를 BG1 타일 512–639로 올린다.
  - 호출: 9F:9727 → 00:B5D6(맵), 9F:9921 → 00:B79D(타일), 둘 다 00:B904 해제.
- 한 맵 절반(64x32)에 그림 네 장이 사분면으로 들어 있고, 장면마다 스크롤로 한 사분면(32x16 칸)만 창에 보인다. 예: 맵 77 절반 0 = 고릴라 얼굴(3D, 94/0) · 석판(40, 94/2, 왼쪽 아래) · 캠프 수칙 칠판(41, 95/0, 오른쪽 위) · 쥐(42, 95/2). 같은 맵이나 타일 에셋을 쓰는 다른 장면이 있으므로, 맵 칸은 자기 사분면 안에서만, 타일은 자기 창(128타일) 안에서 다른 보이는 칸이 쓰지 않는 번호만 고친다(`tools/scene_text.py`).
- 맵 78 절반 1은 포스터(4D, 99/0) 외에 4E–55(타일 100 등)도 쓴다 → 포스터 제목은 맵을 고치지 않고 제목 전용 타일 28장만 제자리에서 다시 그린다(`tools/poster_title.py`).
- 검증 방법: `work/scene_force.py`로 포스터를 여는 순간 `$358C`를 원하는 장면 번호로 바꿔 화면을 띄운다(snes9x는 SA-1 I-RAM을 FillRAM+0x3000에 둠). 실제 진행 경로로 연 화면은 아니므로, 장면 진입 조건(대사·이벤트)은 별도 확인 대상이다.

### 6.8 스태프 크레딧 (2026-10-06)

- LZ 62 = 2bpp 글자판 128자(16x16, 글자 g의 왼쪽 위 타일 = (g // 8) × 32 + (g % 8) × 2, 오른쪽 +1, 아래 +16/+17). LZ 63 = 크레딧 배치: 글자 하나당 맵 값 1개(팔레트 3 | 왼쪽 위 타일), 한 줄 32칸, 0x1EE = 빈칸, 0–47줄이 실제 크레딧(48줄 이후는 쓰이지 않는 채움). 가운데 정렬 = 시작 칸 (32 − 글자 수) // 2.
- 글자 127번 칸의 왼쪽 위 타일이 0x1EE(빈칸 표시)라 글자로 쓸 수 없다. 이름에 쓰인 글자(デバックチーム·SMC·尾崎裕ー의 ー 포함)와 ・를 빼면 빈 칸은 36개.
- 엔딩까지 진행할 수단이 아직 없어 화면 확인은 못 했다(로더도 정적으로는 못 찾음: 표 기반 호출). 렌더는 에셋 두 개로 재구성해 확인했다.
